# ── AST parsing (semantic chunking) ────────────────────────────────────────────
# A grammar built against a newer ABI than the runtime fails at `Language()`
# with "Incompatible Language version N", not at install time, and the package
# metadata does not prevent it: every grammar below declares its tree-sitter
# range under a `core` extra that pip does not enforce. Compatibility here was
# established by loading each grammar and parsing a sample. On the previous
# 0.23 runtime that check rejected the current release of five of them.
#
# Raising the runtime is therefore the prerequisite for raising any grammar.
# Verified on the 0.26 runtime: semantic chunking over the reference corpus is
# byte-identical to the 0.23 pin, so this upgrade changed compatibility only.

# Dockerfile is the one grammar with an incomplete distribution. 0.2.0 publishes
# wheels for macOS arm64 and Linux x86_64 only, with no source distribution, so
# it cannot be installed in an arm64 Linux container — which is what Docker
# Desktop builds on Apple Silicon. The marker skips it there; `_parser_for`
# degrades to line windows and logs when the package is absent, so the build
# succeeds everywhere and the loss is announced rather than silent.
#
# The consequence worth knowing: Dockerfiles are chunked semantically on macOS
# and on x86_64 Linux, and windowed on arm64 Linux. That is a platform-dependent
# index, which is a real wart. Remove this line and the registry entry if you
# would rather have one behaviour everywhere.
#
# It also returns the old integer language handle, which `Language()` accepts
# with a DeprecationWarning. Suppressed at the call site.
tree-sitter-dockerfile==0.2.0; platform_machine != "aarch64"    # .dockerfile
